ორი ცნება

Authentication vs Authorization

Authentication

პასუხობს: ვინ ხარ?

ვინაობის დადასტურება — პაროლი, OTP, biometric, SSO. შედეგი ერთია: ცნობილია მომხმარებელი თუ უცნობი.

ანალოგია: პასპორტის შემოწმება საზღვარზე — ადასტურებს ვინაობას, არაფერს ამბობს სად შეგიძლია შესვლა.

POST /auth/login

{ email, password } → 200 OK + tokens

Authorization

პასუხობს: რისი უფლება გაქვს?

უფლებების შემოწმება — roles, permissions, scopes. შედეგი ყოველ action-ზე ცალკეა: ნებადართული თუ აკრძალული.

ანალოგია: ოფისის ბარათი — ვის ეკუთვნის უკვე ცნობილია, კითხვა ისაა, რომელ ოთახებში ეღება კარი.

DELETE /posts/482

{ role: "viewer" } → 403 Forbidden

ერთი ნაცნობი სცენარი · დააკლიკე

შედიხართ Gmail-ში პაროლით — და შემდეგ ვერასდროს ხედავთ სხვისი ინბოქსის შემცველობას. ორივე ეს ფაქტი ერთი და იმავე ცნების ნაწილია?

არა — ორივე ცნება ერთ სცენარშია

პაროლით შესვლა = Authentication (ვინ ხარ). მხოლოდ საკუთარი ინბოქსის ხედვა = Authorization (რისი ნახვის უფლება გაქვს). პირველი ხდება ერთხელ, login-ზე. მეორე მოწმდება ყოველ request-ზე, ცალკ-ცალკე.

JWT

სამი ნაწილი,
წერტილით გაყოფილი

JSON Web Token არის სამი base64url ბლოკი, წერტილებით შეერთებული: header.payload.signature.

header — ალგორითმი, JWT ტიპი. საჯაროა.
payload — claims: ვინ, როდის, რამდენ ხანს. დაშიფრული არაა — ვინც წაიკითხავს, დაინახავს.
signature — header+payload-ის HMAC. ადასტურებს, რომ არავის შეუცვლია.

ესე იგი: JWT არის signed, არა encrypted. ის იცავს მთლიანობას (tamper-proof), არა კონფიდენციალურობას.

lifecycle

logout-მდე

ერთი token-ის სასიცოცხლო ციკლი ექვს ნაბიჯად. მომხმარებელი მხოლოდ პირველ და ბოლო ნაბიჯს ხედავს — შუალედური ხუთი ავტომატურია.

  1. 1Login. POST /auth/login — სერვერი ამოწმებს credentials-ს.
  2. 2სერვერი აბრუნებს ორ token-ს. Access (მოკლევადიანი) + Refresh (გრძელვადიანი).
  3. 3Access token ერთვის ყოველ request-ს. Authorization: Bearer <token>.
  4. 4Access token ვადა გადის. შემდეგი request სერვერისგან 401-ს იღებს.
  5. 5apiFetch() ავტომატურად ითხოვს ახალს. Refresh token-ით — მომხმარებელი ვერაფერს ამჩნევს (silent refresh).
  6. 6Refresh token-იც ვადაგასულია? მომხმარებელი გამოდის სისტემიდან და უბრუნდება login გვერდს.

შენახვა

სად ვინახავთ
token-ებს?

ოთხი ვარიანტი, ოთხი ტრეიდ-ოფი — XSS-ის (მოპარვა JS-ით) და CSRF-ის (browser-ის თვითნებური გაგზავნა) რისკებს შორის.

localStorage ადვილად ხელმისაწვდომია JS-იდან — ესე იგი ნებისმიერი XSS სკრიპტისთვისაც. ინახება reload-ებს შორის.

JSapi.js
import { getAccessToken } from './auth.js';

export function authFetch(url, options = {}) {
  const token   = getAccessToken();
  const headers = new Headers(options.headers);

  // login / register request-ებზე token არ ერთვის
  if (token && !url.includes('/auth/')) {
    headers.set('Authorization', `Bearer ${token}`);
  }

  return fetch(url, { ...options, headers });
}

თუ 5 request ერთდროულად მიიღებს 401-ს, არასწორი კოდი ხუთჯერ გამოიძახებს /auth/refresh-ს — race condition, ზოგი მარცხდება.

// ერთი გაზიარებული Promise ყველა request-ისთვის
let refreshPromise = null;

function refreshOnce() {
  refreshPromise ??= fetch('/auth/refresh', {
      method: 'POST', credentials: 'include'   // 🍪 httpOnly
    })
    .then(r => r.ok ? r.json() : Promise.reject(r))
    .then(({ accessToken }) => setAccessToken(accessToken))
    .finally(() => { refreshPromise = null; });
  return refreshPromise;
}

export async function apiFetch(url, options = {}) {
  const res = await authFetch(url, options);
  if (res.status !== 401) return res;

  // ყველა request ელოდება ერთსა და იმავე refresh-ს
  try   { await refreshOnce(); }
  catch { logout(); throw new Error('session expired'); }

  return authFetch(url, options);   // retry ახალი token-ით
}

export const getUser         = () => user;

export function authGuard(to) {
  if (isAuthenticated()) return true;
  return `/login?returnUrl=${encodeURIComponent(to)}`;
}

export const roleGuard = role => () =>
  roles().includes(role) || '/403';
JSrouter.js
const routes = {
  '/login': { render: renderLogin },
  '/403':   { render: renderForbidden },
  '/admin': { render: renderAdmin, guards: [authGuard, roleGuard('admin')] },
};

export function navigate(to) {
  const route = routes[new URL(to, location.origin).pathname];
  for (const guard of route.guards ?? []) {
    const result = guard(to);
    if (result !== true) return navigate(result);   // redirect
  }
  history.pushState(null, '', to);
  route.render();
}
